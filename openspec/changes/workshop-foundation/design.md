## Context

See `proposal.md` for the motivation. The repository has one initial commit. The untracked scaffolding next to it was generated by OpenSpec 1.13.0 for Claude Code only: `.claude/`, `openspec/`, a hello-world `pyproject.toml` and `main.py`, `.python-version` (3.12), and the master preparation document in `docs/`.

Four facts from the exploration shape every decision below. Each was checked, not assumed:

1. **The stack resolves together** - 150 packages on CPython 3.12 - but only with `rf-mcp[web,api]` (D2).
2. **`robotframework-browser-batteries` ships its own Node runtime** (`BrowserBatteries/bin/node`). It installs the Playwright browsers *inside* `.venv`, under `Browser/wrapper/node_modules/playwright-core/.local-browsers/` (D4).
3. **The OpenSpec CLI is npm-only**, with `engines: node >=20.19.0`, so Node.js remains a prerequisite (D5).
4. **The shop's space rule is the GitHub username format**, case-insensitive and normalized to lowercase. The shop resolves the space from the `X-Workshop-Space` header before `?space=`, the `workshop_space` cookie, and `default` (D7).

## Goals / Non-Goals

**Goals:**
- A participant with the prerequisites reaches a green `setup-check` in five commands, on any supported platform.
- Every later change builds on a fixed contract: the pinned stack, `SHOP_URL`/`SHOP_SPACE`, the `local`/`shared` profiles, and the two spec namespaces.
- Nothing in the repository can quietly drift from what `setup-check` verifies.

**Non-Goals:**
- Tests, resources for the suite, and the browser-side implementation of the space contract (`baseline-suite`).
- Lab content, skills, hooks and MCP snippets (`workshop-labs`), and CI or the site (`ci-and-site`).
- Installing anything for the participant: `setup-check` diagnoses, it never repairs.

## Decisions

### D1. uv, exact pins, a committed lock, Python 3.12

Dependencies are pinned with `==` in `pyproject.toml` and resolved into a committed `uv.lock`. `uv sync --locked` is the only install command, and `[tool.uv] required-version` pins the uv release that created the lock.

| Package | Version | Note |
|---|---|---|
| `robotframework` | 7.5 | |
| `robotframework-browser` | 20.5.0 | with `robotframework-browser-batteries==20.5.0` (D4) |
| `robotframework-requests` | 0.9.7 | API tests (Module 5 stretch) |
| `robotcode[all]` | 2.7.0 | D3 |
| `rf-mcp[web,api]` | 0.35.0 | D2 |
| `robotframework-heal` | 0.4.0 | healing listener (Module 8) |
| `python-dotenv` | pinned direct | reads `.env` (D7); present transitively already, but not relied on |

Python 3.12 is the repository's existing `.python-version`. Every pinned package supports Python 3.10 and newer, and nothing needs the 3.13 that the RBCN workshop used, so the more conservative interpreter wins on corporate machines. uv installs the interpreter itself, so participants do not manage Python.

*Alternatives:* the master document's `requirements.txt` with `pip install` pins only direct dependencies, which leaves 140-odd transitive packages free to drift - the exact failure the master document ranks first. Poetry or PDM would add a second tool to a stack where demo-webshop and RBCN already use uv.

### D2. `rf-mcp[web,api]`, never `rf-mcp[all]`

`rf-mcp[all]==0.35.0` requires `platynui-cli==0.13.0.dev2` and `robotframework-platynui==0.13.0.dev2`, desktop-automation pre-releases. uv refuses to resolve them without `--prerelease=allow`. `[all]` would also pull Django, `model2vec` and `sentence-transformers` (and so PyTorch). The workshop needs `[web]`, for Browser (and SeleniumLibrary), and `[api]`, for RequestsLibrary.

*Alternative:* allowing pre-releases, which breaks the stable-only requirement for a desktop feature nobody uses.

### D3. `robotcode[all]`, invoked through `uv run`

The five habits Module 4 teaches all exist in 2.7.0 with `[all]`: `discover`, `libdoc`, `robot-debug`, `repl` and `results`. The narrower extras would each need to be proven to include `results`, and the size saving is small. The documented, and only, invocation is `uv run robotcode …`: this form cannot pick up a pipx or uvx installation, which would not see the project's libraries (the master document's Module 4 warning).

### D4. Browser batteries and `rfbrowser install chromium`

With the batteries package installed, `rfbrowser install chromium` downloads only the browser (plus `--with-deps` on Linux for system libraries). `rfbrowser init` must **not** be run, because it installs the separate Node dependencies, the step that fails behind corporate proxies. Two consequences:

- The browsers live inside `.venv`. Deleting or recreating the environment silently removes them, so `setup-check` checks for the binary, not just the Python package.
- The batteries wheels define the supported platforms: `win_amd64`, `macosx_13_0_arm64` and `macosx_13_0_x86_64`, `manylinux_2_28_x86_64` and `manylinux_2_28_aarch64`. Windows on Arm and macOS before 13 fall back to Browser without batteries plus `rfbrowser init`, which needs Node and npm.

*Alternative:* SeleniumLibrary. Rejected, because Browser is what the master document, `robotframework-heal` and rf-mcp centre on.

### D5. Node.js stays a prerequisite, OpenSpec is pinned

OpenSpec 1.13.1 is published only to npm and requires Node 20.19 or newer, and Module 5 depends on it. The GitHub Copilot CLI needs Node too; Claude Code's native installer does not. `SETUP.md` therefore requires Node 20.19+ (22 LTS recommended) and installs `@fission-ai/openspec@1.13.1` globally. The batteries package (D4) still earns its place: it removes Browser's *own* npm step, which is the fragile one.

*Alternative:* `npx @fission-ai/openspec@1.13.1` on every call. It needs the same Node, and is slower and noisier inside agent sessions.

### D6. Where each pin lives, and how `setup-check` reads it

| Pin | Lives in | Read by |
|---|---|---|
| Python packages | `pyproject.toml`, `uv.lock` | `uv sync`; `setup-check` via `uv.lock` |
| OpenSpec, minimum Node, Docker, `gh` | `[tool.workshop]` in `pyproject.toml` | `setup-check` via `tomllib` |
| Shop image tag | `shop/compose.yaml` only | Docker Compose; `setup-check` |

`pyproject.toml` hosts the non-Python pins because maintainers already edit it for every version bump. The image tag cannot move there, because Compose cannot read TOML, so the compose file is its single home. `SETUP.md` repeats the numbers for humans; the risk that entails is covered under Risks.

### D7. Shop access: compose file, two settings, two profiles, one header

- **`shop/compose.yaml`**: one service `shop` from `ghcr.io/manykarim/demo-webshop:<tag>` on port 9090, with no volume. As in the demo-webshop README, `restart` keeps data and recreating resets it:
  - start: `docker compose -f shop/compose.yaml up -d`
  - fresh seed: `docker compose -f shop/compose.yaml up -d --force-recreate`
  - stop: `docker compose -f shop/compose.yaml down`
- **Settings**: `SHOP_URL` and `SHOP_SPACE`. `.env` in the repository root is loaded without overriding the process environment. Without either setting, tools use `http://localhost:9090` and no space.
- **Profiles in `robot.toml`**: `local` (the default) and `shared`. `shared` defaults `SHOP_URL` to `https://demoshop.makrocode.de` and requires a valid space. A variable file resolves the final values (process environment, then `.env`, then the profile default) and stops the run before the first test when `shared` has no valid space. demo-webshop's rollout plan calls this "the workshop repository's `coolify` profile". It is named `shared` here, because participants have no reason to know the hosting.
- **The header, not the query**: every tool sends `X-Workshop-Space` whenever a space is set. The header takes precedence in the shop and is stateless, so it covers page loads, assets and API sessions alike. `?space=` would only set a cookie that later navigations depend on. The helper (D8) implements the header in this change. The suite's browser contexts implement it in `baseline-suite`, as a context-wide extra HTTP header that Playwright applies to every request.

### D8. The `shop` helper

`uv run python -m shop status | presets | preset <name> | reset | wait` is a small stdlib-only Python module in `shop/`.

- **Why a helper rather than curl snippets:** on Windows, `curl` in PowerShell is an alias with different syntax. One Python command behaves identically everywhere, and it is the single implementation of the space rule.
- **Neutral `status`:** reports the version (`/health`), the space, and every preset whose settings all hold in the space's effective flags (from `/api/workshop/presets` and `/api/workshop/status`), or `custom`. Presets are partial and compose: `stage1` sets only the locator flags, so a clean space satisfies both `clean` and `stage1`, and `buggy` applied after `stage2` satisfies both. Naming every satisfied preset is well-defined where "the matching preset" is not. It never prints bug flag names. This avoids advertising the Module 7 answers; it is not secrecy, and the API still answers anyone curious.
- **`reset` is the *space* reset** (`POST /api/workshop/reset`): it removes the space's flags, cart and runtime orders. In local mode without a space, it acts on the local `default` space, which is harmless. It is distinct from the fresh-seed container recreate in D7.
- **Shared-default guard:** with an empty space and a non-loopback `SHOP_URL`, the helper refuses to write before sending anything.
- **`wait`:** polls `/health` until it answers or a timeout expires, for scripts and CI.

### D9. `setup-check`

`uv run python setup-check/check.py` is one file, following the master document's layout, and uses only the standard library and locked packages. Because uv must exist to run it at all, `SETUP.md`'s first step installs uv, and the check only reports uv's version.

| Check | Severity | Module | How |
|---|---|---|---|
| Python | fail | M0 | interpreter matches `.python-version` |
| locked environment | fail | M0 | every installed distribution equals its `uv.lock` version |
| browser runtime | fail | M0 | batteries present, `rfbrowser init` dependencies absent |
| browser binaries | fail | M0 | Chromium present under the Playwright browsers directory |
| browser launch | fail | M0 | headless browser opens `about:blank` and closes |
| container runtime | fail (local) / skip (shared) | M0 | daemon reachable, Compose v2 |
| shop image | fail (local) / skip (shared) | M0 | pinned image present locally; the pull command is printed otherwise |
| shop health | fail | M0 | `SHOP_URL/health` answers; in local mode, with the pinned version |
| space | fail (shared) | M0 | set, valid GitHub-handle format, not `default` |
| coding agent | fail | M2 | at least one of `claude`, `codex` or `copilot` on `PATH`, with its version |
| RobotCode commands | fail | M4 | the five subcommands exist in the project environment |
| RobotCode on `PATH` | warn | M4 | first `robotcode` on `PATH` lies inside `.venv` |
| Node.js | fail | M5 | at least the `[tool.workshop]` minimum |
| OpenSpec | fail | M5 | equals the pinned version |
| GitHub CLI | fail | M7 | installed at the minimum and `gh auth status` succeeds |
| Azure CLI | warn | M7 | optional track |
| healing endpoint | warn | M8 | `HEAL_*` settings present or absent, values never shown |
| platform | warn | - | inside the tested set (D4) |

The output is a human-readable table (pass, warn, fail, skip), plus `--json` for the setup-problem template and `--offline` to skip network checks. The exit status is non-zero on any failure. Secret settings are reported by name only, and a task proves it with a planted fake key. The exact marker that tells an `rfbrowser init` installation apart from a batteries-only one is determined against both flows during implementation, and recorded in the check.

### D10. Agent context and OpenSpec

- **`AGENTS.md`**, under 30 lines: what the repository is, how to install it, how to run the suite with its profiles, how to reach the shop through the helper and the two settings, and that Lab 2 builds the file out.
- **`CLAUDE.md`** is a single `@AGENTS.md` import. Codex and GitHub Copilot read `AGENTS.md` natively, which a task verifies. If Copilot needs `.github/copilot-instructions.md`, that file only points to `AGENTS.md`.
- **OpenSpec integrations:** `openspec init --tools claude,codex,github-copilot` with 1.13.1 regenerates today's 1.13.0 `.claude/` files and adds the Codex and Copilot integrations. The generated files are committed: participants never run `init`.
- **`openspec/config.yaml`:** a `context` explaining the `shop/*` and `workshop/*` namespaces, and a `rules.specs` entry carrying the neutrality rule, worded so that it applies to `shop/*` only. `workshop-labs` later extends the context with the namespace for participants' own changes.

*Alternative:* keeping the neutrality rule only in documentation. Rejected: a configuration rule reaches every agent at the moment it writes a spec.

### D11. Documents

- **`README.md`** carries the five-command quickstart:
  1. fork and clone;
  2. `uv sync --locked`;
  3. `uv run rfbrowser install chromium`;
  4. start the shop;
  5. `setup-check`.
- **`SETUP.md`** covers:
  - the prerequisites table (version, first module);
  - per-OS notes, including `--with-deps` on Linux;
  - the corporate-proxy host list: PyPI and its file host, GitHub and `ghcr.io`, the npm registry, and `cdn.playwright.dev` with its Microsoft fallback;
  - the shared-instance fallback for machines without Docker;
  - the agent choice guide;
  - API keys and their cost, with the spending-cap warning in bold;
  - where to file a setup problem, with the `--json` output attached.
- **`.env.example`** lists `SHOP_URL`, `SHOP_SPACE` and the optional `HEAL_MODEL`, `HEAL_BASE_URL` and `HEAL_API_KEY`, by name only.
- **`.gitignore`** gains the Robot Framework outputs, the healing report directories and `node_modules/`, on top of `.env` and `.venv`.
- **`main.py`** is removed.

## Risks / Trade-offs

- [A corporate proxy blocks PyPI, ghcr.io, npm or the Playwright CDN] → `SETUP.md` lists every host. `setup-check`'s network checks name the failing host. The shared instance removes the Docker and ghcr.io needs; the browser download remains.
- [Docker Desktop is not permitted on work machines] → shared mode needs no container runtime, and `setup-check` skips those checks in that mode.
- [Recreating `.venv` silently deletes the browsers] → `setup-check` fails with the install command, and `SETUP.md` explains why.
- [`SETUP.md` numbers drift from the pins] → `setup-check` prints every expected version from its source, so the guide can defer to it. A consistency check can join `ci-and-site`; until then, the bump procedure in `SETUP.md` lists the files to change together.
- [`robotframework-heal` pulls in AppiumLibrary, and `rf-mcp[web]` pulls in SeleniumLibrary] → accepted as unused weight. Removing them means patching upstream packages.
- [Neutral status is not secrecy] → accepted. The aim is not to advertise the Module 7 answers, not to hide the API.
- [`AGENTS.md` is too thin for a participant who missed Lab 2] → the `solutions` branch (`workshop-labs`) carries a reference `AGENTS.md`.
- [OpenSpec-generated files drift from newer agent versions] → pinned to 1.13.1; regenerating is a reviewed change like any other bump.

## Migration Plan

There is nothing to migrate. This change's implementation turns the untracked scaffolding into the repository's first real commits, regenerates `.claude/` with OpenSpec 1.13.1, and adds the Codex and Copilot integrations. Rolling back means reverting those commits.
